# About / Contact 나무마크 편집기 V1 명세

- 상태: 구현 및 로컬 공개 화면 검증 완료, OWNER 저장 검증은 배포 단계 대기
- 최종 결정일: 2026-08-02
- 대상: `about.html`의 About / Contact 통합 문서

## 1. 제품 결론

V1은 여러 사람이 함께 편집하는 위키 엔진이 아니다. 사이트 소유자가 자신의 About을 **나무위키처럼 원문으로 작성하고 미리 본 뒤 공개하는 전용 편집기**다.

유지하는 것:

- 기존 `about.html` 주소와 90년대 개인 홈페이지 화면
- 프로필 표, 목차, 번호 섹션, 섹션별 `[편집]`
- OWNER 한 명만 편집
- `site_settings.about_wiki_document` JSON 한 건을 덮어쓰는 저장 방식
- 프로필 표와 왼쪽 사이드바의 데이터 공유
- 저장 queue, 미저장 이탈 경고, 배포 자동 새로고침 방지
- 기존 미디어 업로드와 원본 보존

제외하는 것:

- 리비전과 역사
- diff와 되돌리기
- 방문자 편집·편집 요청
- 문서별 ACL
- 토론, 역링크, 분류, 템플릿, include
- 여러 위키 문서 생성·이동·삭제

## 2. 현재 구조와 변경점

### 이전

```text
BlockNote WYSIWYG
→ HTML
→ about_wiki_document.sections[].body
→ 공개 화면 innerHTML
```

### V1

```text
나무마크 원문 textarea
→ 안전한 About 전용 렌더러
→ 저장 전 미리보기
→ 기존 JSON에 source + 호환용 body 덮어쓰기
→ 공개 화면도 같은 렌더러 사용
```

새 PocketBase 컬렉션이나 마이그레이션은 만들지 않는다.

## 3. 데이터 형식

문서 전체는 계속 `site_settings.about_wiki_document`에 저장한다.

```json
{
  "contentSchemaVersion": 2,
  "title": "김찬수",
  "profileRows": [],
  "sections": [
    {
      "id": "overview",
      "title": "개요",
      "format": "namumark-v1",
      "source": "나무마크 원문",
      "body": "구버전 롤백용 렌더 HTML",
      "legacyBody": "최초 변환 전 HTML"
    }
  ]
}
```

- `source`가 본문의 기준 데이터다.
- `body`는 이전 배포본이 읽을 수 있는 호환 캐시다.
- `legacyBody`는 기존 HTML 섹션을 처음 변환할 때만 보존한다.
- 프로필 행은 기존 구조와 아이콘·링크 표현을 유지하되, 공개 렌더 때 허용 태그와 안전한 URL만 남긴다.
- 빈 `source`도 의도적인 빈 본문이므로 값 존재 여부로 형식을 판별한다.

## 4. 기존 문서 전환

기존 운영 JSON은 자동으로 일괄 덮어쓰지 않는다.

1. `source`가 없는 기존 섹션은 HTML을 메모리에서 나무마크로 변환해 안전하게 공개 렌더한다.
2. OWNER가 그 섹션의 `[편집]`을 누르면 변환된 원문이 textarea에 보인다.
3. 저장 전 미리보기로 변환 결과를 확인한다.
4. 저장했을 때만 `source`, `format`, 호환용 `body`를 기존 JSON에 덮어쓴다.
5. 최초 변환 전 `body`는 `legacyBody`에 보존한다.
6. 다른 섹션의 이동·저장 때문에 아직 검토하지 않은 섹션이 자동 변환되지는 않는다.

운영 배포 전에는 기존 JSON을 별도로 백업한다. 앱 안의 역사 기능은 만들지 않는다.

## 5. OWNER 편집 흐름

1. OWNER가 섹션 제목의 `[편집]`을 누른다.
2. 현재 나무마크 원문이 Courier 계열 textarea에 열린다.
3. 원문을 직접 수정한다.
4. `미리보기`를 누르면 아래쪽에 공개 화면과 같은 결과가 보인다.
5. `미디어 넣기` 또는 drag & drop으로 파일을 올리면 현재 커서 위치에 문법 토큰이 삽입된다.
6. `저장`하면 기존 JSON 한 건을 덮어쓴다.
7. 저장 실패 시 textarea와 dirty 상태를 유지한다.
8. `취소`하면 저장하지 않은 수정 내용을 버리고 원래 섹션으로 돌아간다.

편집 요약, 저장 전 diff, 리비전 번호는 없다.

## 6. V1 문법

V1은 About에 실제 필요한 부분집합만 지원한다.

| 기능 | 입력 예시 |
| --- | --- |
| 굵게 | `'''굵게'''` |
| 기울임 | `''기울임''` |
| 밑줄 | `__밑줄__` |
| 취소선 | `~~취소선~~` |
| 외부 링크 | `[[https://example.com|표시 이름]]` |
| 이메일 | `[[mailto:name@example.com|메일]]` |
| 같은 문서 이동 | `[[#about-section-contact|연락처]]` |
| 비순서 목록 | 줄 시작 공백 뒤 `* 항목` |
| 순서 목록 | 줄 시작 공백 뒤 `1. 항목` |
| 인용 | `> 인용문` |
| 수평선 | `----` |
| 각주 | `[* 각주 내용]` |
| 표 | `|| 셀 1 || 셀 2 ||` |
| 표 머리글 | `|| '''시기''' || '''내용''' ||` |
| 접기 | `{{{#!folding 제목`부터 닫는 `}}}`까지 |
| 리터럴 블록 | 단독 `{{{`부터 닫는 `}}}`까지 |
| 강제 줄바꿈 | `[br]` |
| 미디어 | `[[파일:안전한 URL|설명]]` |

섹션 제목과 문서 목차는 JSON의 `sections[].title`과 `id`가 계속 관리한다. 본문 안 소제목은 제한적으로 렌더하지만 문서 상단 목차에는 섞지 않는다.

의도적으로 지원하지 않는 문법:

- raw HTML
- 임의 CSS·색상·스타일
- 표 셀 병합과 크기 속성
- 임의 iframe
- 분류, 틀, include, 리다이렉트
- 수식과 실행형 매크로

## 7. 렌더링 안전 원칙

- 원문에 들어온 HTML은 실행하지 않고 일반 텍스트로 표시한다.
- 렌더러가 직접 생성하는 제한된 HTML만 공개한다.
- 링크는 `http:`, `https:`, `mailto:`, 같은 사이트 상대경로와 문서 앵커만 허용한다.
- `javascript:`, `data:`, `file:`, `blob:`, protocol-relative 외부 링크는 거부한다.
- 사용자 문자열은 텍스트와 속성에 맞게 각각 escape한다.
- 이미지·영상·오디오·PDF만 미디어 토큰으로 삽입한다.
- 프로필 값의 기존 아이콘·링크 HTML도 태그·속성 allowlist를 거쳐 script, event handler, 위험 URL을 제거한다.
- 미리보기와 공개 화면은 반드시 같은 렌더 함수를 사용한다.
- 깨진 문법이 있어도 원문을 삭제하거나 자동 교정하지 않는다.

## 8. 공개 화면과 디자인

다음 구조를 유지한다.

```text
90s marquee / 노란 banner
→ 1140px 데스크톱 shell
→ sidebar + content
→ top navigation
→ 문서 제목
→ 오른쪽 프로필 표 + 왼쪽 목차
→ 번호 섹션
```

- OWNER 편집기는 현재 노란색 dashed `.about-editor` 안에 나타난다.
- split pane, modal, rounded card, shadow, 현대식 위키 대시보드를 사용하지 않는다.
- textarea와 미리보기는 위아래 수직 흐름으로 배치한다.
- 넓은 표와 리터럴 블록만 자체 영역에서 가로 스크롤한다.
- 섹션 제목과 `[편집]` 링크 전체를 스크롤 컨테이너에 넣지 않는다.

현재 운영 공개 About은 320px과 390px에서 페이지 전체 overflow가 확인되지 않았다. 모바일 작업은 기존 버그 수정이 아니라 새 editor·표·code가 overflow를 만들지 않게 하는 회귀 방지다.

## 9. 인수 기준

### 공개 열람

- 비로그인 방문자는 편집 UI를 보지 않는다.
- 기존 HTML 문서와 새 원문 문서가 모두 빈 화면 없이 렌더된다.
- 프로필 표, 목차, 번호 섹션, Contact와 기존 앵커가 유지된다.
- 표, 목록, 링크, 각주, 접기와 미디어가 의미에 맞게 보인다.
- 정적 fallback은 CMS 또는 렌더러 장애 때도 남는다.

### OWNER 편집

- 전체 사이트의 공용 WYSIWYG 편집기는 건드리지 않고 About만 원문 textarea를 쓴다.
- 미리보기는 저장하지 않으며 공개 화면과 같은 렌더 결과를 만든다.
- 저장은 기존 JSON 한 건을 덮어쓴다.
- 저장 queue가 연속 요청을 직렬화한다.
- 저장·파서 오류, 탭 이동, 배포 새로고침 때 작성 중 원문을 잃지 않는다.
- 기존 HTML 섹션은 해당 섹션을 처음 저장할 때만 전환된다.
- 미디어 선택·drop·paste 후 파일 순서대로 토큰이 삽입된다.

### 보안

- script, event handler, raw HTML이 실행되지 않는다.
- 위험한 링크와 미디어 URL이 `href`나 `src`가 되지 않는다.
- 깨진 문법이 렌더러 예외나 문서 전체 손실을 만들지 않는다.
- 같은 원문은 항상 같은 HTML을 만든다.

### 모바일·접근성

- 모바일 320, 375, 390, 640px에서 문서와 editor가 콘텐츠 경계 안에 있다.
- 데스크톱 1200, 1440px에서 기존 1140px shell과 infobox·TOC 배치를 유지한다.
- `body overflow-x:hidden`만으로 잘림을 숨긴 상태는 통과로 보지 않는다.
- 표와 code만 자체 가로 스크롤을 가진다.
- textarea에 실제 label이 연결된다.
- 미리보기·미디어·저장·취소는 native button이다.
- 모바일 OWNER 버튼의 hit area는 최소 44px을 목표로 한다.
- focus 표시, 상태 `aria-live`, 오류 `role=alert`가 있다.
- 각주 링크와 표 머리글이 의미 있는 HTML을 사용한다.

## 10. 검증 계획

- parser 정상·깨진 입력 fixture
- XSS와 위험 URL fixture
- legacy HTML 변환 fixture
- source 저장과 호환 body 생성 검사
- 기존 save queue·dirty guard·섹션 이동 회귀 검사
- production build
- 공개 About 데스크톱 1200px 이상 브라우저 확인
- 모바일 390px 브라우저 경계 측정
- 인증된 OWNER 화면에서 원문 → 미리보기 → 저장 → 재로딩 확인

마지막 OWNER 저장 검증은 운영 데이터가 바뀌므로 배포 단계에서 운영 백업 후 수행한다.

## 11. 향후 확장

실제 필요가 생기기 전에는 구현하지 않는다.

- 리비전·history·diff·되돌리기
- 방문자 편집 요청
- 여러 편집자와 문서 ACL
- 여러 위키 문서와 내부 링크 그래프

현재 제품 목표에는 이 기능들보다 소유자가 편하게 원문을 쓰고 정확히 미리 보는 경험이 더 중요하다.
