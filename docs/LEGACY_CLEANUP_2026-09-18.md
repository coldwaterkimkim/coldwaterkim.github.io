# 2026-09-18 레거시 화면 정리

## 범위

현재 Sketchbook + Crayon 화면과 기능을 유지하면서, 숨겨진 옛 화면에 대한 의존과 실행되지 않는 과거 컨트롤러를 제거한다. 제품 기준은 `WEBSITE_DIRECTION.md`이며, 이번 정리는 새로운 디자인 변경이나 데이터 변환이 아니다.

## 검증 변경

옛 화면의 존재를 강제하던 검사를 현재 실행 구조에 맞췄다. 기능 검증을 통째로 끄지 않았다.

- `qa:writing`: 미사용 프로그램실 컨트롤러 존재 조건을 제거하고, 재사용 가능한 로컬 엔진·인증 전송의 유지 조건으로 교체. 나머지 작성·첨부·편집·구 URL 회귀 검사는 유지.
- `qa:content-views`: 옛 카테고리 컨트롤러 대신 공통 Records 서비스의 카테고리별 식별자, 공개 상태, 실제 상세 화면의 조회 호출을 검사. 중복 방지·OWNER 제외·비공개 제외·오류 처리·스키마 검증 유지.
- `qa:askme`: 이미 종료된 UI 및 내비게이션의 존재 조건을 제거. 종료 URL의 홈 이동, 순수 표시 로직, 공개 피드의 비공개 내용 차단, 암호·영수증 토큰 해시, 인증된 삭제 경로 등 39개 검증 유지.

위 세 검사는 수정 후 통과했다. `qa:file-tools`도 100개 검증을 통과했다.

공통 초기화 모듈 분리에 따라 다음 검사도 현재 실행 경로로 이전했고 통과했다.

- `qa:entry-gate`: 더 이상 활성화하지 않는 옛 입장 페이지 대신 `bgm-runtime.js` → `bgm-consent.js` 연결을 검사. 기존 입장 요약 순수 함수의 호환성 검사 유지(30개).
- `qa:webring`: 옛 사이드바 초기화 요구를 제거하고 순수 링크/이웃 선택, 공개 자료 필터 계약 유지(11개).
- `qa:archive`: 기존 날짜 정렬·공개 시점·방명록 답글 계약 유지. 홈페이지의 사라진 미리보기 8행 대신 현재 공통 셸의 앨범 이동과 기존 주소 리다이렉트 확인.
- `qa:visitor-counter`: 모의 PocketBase를 통한 방문 생성·OWNER 제외 동작 유지. 배너 존재와 관계없는 명시적 방문/분석 초기화를 검사(11개).
- `qa:writing`: 제거된 문서 HTML 교체형 SPA의 base 변경 요구를 제거하고, 현재 공통 셸의 원점 기준 링크 및 기존 상세 URL 호환성 유지.
- `qa:about-wiki`: 저장하지 않은 편집 내용을 보호하는 갱신 차단 검사를 분리된 `site-version.js`에 연결(30개).

## 공통 셸과 기능 분리

- 홈·records 미리보기·About·앨범·방명록·방명록 답글 본문을 `#sketch-content`에 직접 배치했다. 옛 표·배너·사이드바·푸터를 제거했다.
- `js/site.js`와 `js/unified-shell.js`를 삭제하고 필요한 기능을 전용 모듈로 분리했다. 셔플은 숨겨진 버튼을 대신 클릭하지 않고 재생 함수를 호출한다.
- 공개 HTML은 `public-base.css`를 사용한다. 기존 `styles.css`는 SSR·과거 경로 사용처 때문에 보존한다.
- 음악 관리의 MP3 업로드·편성표·자르기·삭제와 미저장 편집 보호를 유지했다. 방문 집계는 배너 DOM과 분리했다.

## 통합 검증

- 빌드, BGM 102개 및 재생 동의 생명주기, 방명록 22개, 앨범 41개, SEO 26개 검사 통과.
- Records 실제 DOM 핸들러 검사: 저장 상태, 첨부/저장 실패 복구, 과거 본문·크롭·임베드·댓글 동작 통과(모의 I/O).
- 로컬 실제 브라우저: 공개 기록·About 저장 소개/SNS·앨범 24개 썸네일·방명록 렌더링, 페이지 오류 없음.
- 데스크톱 홈 높이 1000/1000으로 스크롤 없음, 전체 보기 실제 스크롤 이동 확인. 음악 재생·다른 곡 셔플·일시정지 및 페이지 이동 후 정지 유지 확인.
- 음악 관리는 브라우저에서 인증 여부만 모의 처리하고 API 쓰기를 차단한 상태로 편성표 열기를 확인했다. 운영 DB에 시험 글이나 음악을 저장하지 않았다.
- `verify-bgm-owner-runtime.mjs`는 실제 업로드 이벤트를 모의 I/O로 실행하여 기존 곡 유지·신규 곡 추가·설정 저장·잘못된 삭제 방지·편성표 열기/닫기를 검사한다. Records DOM 검사와 동일하게 `CWK_DOM_PARSER_MODULE`에 linkedom ESM 경로를 지정해 실행한다. 분리 중 발견한 함수 수입 누락을 수정하고 이 검사로 재발을 방지했다.

## 유지해야 할 경계

- 공개된 과거 URL과 리다이렉트, `posts/view.html`·`daily/view.html`의 SSR 본문/메타데이터 계약.
- `legacyHtml` 및 기존 본문·미디어 렌더링, 업로드, 로그인·편집, 실제 음악·방명록·앨범 데이터.
- PocketBase 스키마·백엔드·마이그레이션·원본 미디어. 이번 정리에서 DB 쓰기·변환은 수행하지 않는다.
- `heritage/2026-09-16-retro/`의 철학서·화면 기록, 의도적으로 격리된 작성/미리보기 도구.
- 과거 CSS처럼 참조가 섞인 파일은 파일 나이만으로 전체 삭제하지 않는다. 실행 중인 화면·관리자·편집기 사용처를 분리한 뒤 불필요한 선택자만 정리한다.
